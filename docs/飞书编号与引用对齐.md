# 飞书编号与引用对齐

在用户要求把素材和成片收录到飞书时使用。已有表结构优先复用；通过当前可用的飞书连接器或 `lark-base` Skill 读写，不把本次项目的 Base token、记录 ID 或路径写死到可复用工具中。

## 三层编号

| 标识 | 含义 | 使用规则 |
|---|---|---|
| `S1…Sn` | 成片借鉴的爆款结构 | 文案、配音、分镜、成片、飞书使用同一结构号；V1/V2为同一结构的版本 |
| `TC-20261105-021` | 固定素材编号示例 | 平台简称+入库批次日期+三位流水号；已存在的稳定编号直接沿用；创建后不因排序、补采或筛选变化而改号 |
| 平台原视频 ID | 原平台唯一视频标识 | 按文本保存，保留完整数字；对应链接与本地原片文件名，避免长整数精度丢失 |

表格行号只是当前显示位置，不能充当素材编号。采集子 Skill 如果按热度重排序号，将它单独保留为排序号，不覆盖已用于引用的固定素材编号。`A03/X01/P04B` 等是工程中的镜头窗号，重扫可能改变；只能作为辅助信息。

下载文件已有命名约定时无需重命名，但必须维护「固定素材编号 → 原视频ID → 原链接 → 本地文件名/路径」映射。原片、字幕清理片、静帧衍生片共享来源映射；派生片不能被误当成另一条原创来源。

## 素材库

| 字段 | 类型/内容 |
|---|---|
| 素材编号 | 文本；建议作为主字段，让关联记录直接显示固定编号 |
| 平台原视频ID | 文本；TikTok已有「TikTok视频ID」字段时直接复用 |
| 原视频链接 | 链接或文本URL |
| 原片路径或附件链接 | 文件位置；本地路径标明“本机路径” |
| 引用标签 | 多选；按结构号和用途组合 |

标签示例：`S1｜主结构对标`、`S1｜脏污开场`、`S1｜脏刷/冲水画面`、`S1｜产品/用法画面`。用途按当前品类实际内容命名；后续结构使用 `S2｜主结构对标` 等。一条素材可同时拥有多个结构的标签，更新时合并已有值，不能抹掉其他成片的引用。

主结构对标说明借鉴哪条原片的叙事功能顺序；画面来源说明实际用了哪条原片的镜头，两者分别填写。不能把“用了开头画面”写成“借鉴了整条结构”。

## 成片生产表

| 字段 | 类型/内容 |
|---|---|
| 成片编号 | 如 `品类_S1_MS_AI_V2`，包含结构号及版本 |
| 主结构对标 | 关联素材库的主对标记录，通常一条 |
| 画面来源 | 关联素材库中实际用到的全部来源记录 |
| 参考视频与节奏说明 | 主对标编号/原链接、原片各段时间与功能、新片对应时间与改编说明 |
| 分镜与素材编号 | 每镜成片起止 → 固定素材编号 → 原片起止 → 用途；窗号作为辅助信息 |
| 目标时长秒 | 用户要求的每条时长；不把整批总时长写入此列 |
| 实测时长秒 | 最终媒体探测值；若已有类似字段则复用 |

逐镜示例：

| 成片时间 | 素材编号 | 原片时间 | 用途 | 工程窗号 |
|---|---|---|---|---|
| 00.000–02.033 | TC-20261105-003 | 00.200秒静帧 | 脏污钩子、轻推近 | X01 |
| 02.033–04.053 | TC-20261105-014 | 14.090–16.110 | 脏刷放大痛点 | P04B |
| 04.053–06.433 | TC-20261105-021 | 15.027–17.407 | 产品实物 | M03 |

静帧写出原片取帧时间，变速写出源入点/出点和速度；不能把衍生文件自身的时间当作原片时间。若开头做了强化、压缩或重排，直接说明原片功能与本版改法，不声称逐镜复刻。不同马桶的镜头不能被标成同一马桶的效果前后对比。

## 写入与验收

1. 读取现有字段和目标记录，定位固定素材编号、平台ID和记录ID；存在则更新，避免重复创建。
2. 仅补缺少的字段。单选/多选选项先建好；关联指向真实素材记录ID，不能把显示行号当记录ID。
3. 写入成片的关联、说明和逐镜来源，再合并素材引用标签。将编号映射与逐段对照保存在项目中，在线表里也填写可直接阅读的说明，不能只放本机MD路径。
4. 汇总写完后回读：核对主结构对标记录、所有画面来源、标签和原片时间。确认字段在交付视图中可见。飞书刚写完可能延迟，先看写入响应，再适当等待并统一验收，避免重复创建。
5. 在交付回复给出飞书入口和固定素材编号，明确哪条是主结构、哪条仅供画面。

不要求飞书入库的任务，在项目清单中保留同样的固定编号和来源关系即可。
